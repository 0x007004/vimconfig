# RTA Integration Agent — Minimum Harness Demo

A self-contained, runnable demo of an **RTA media integration agent** built on
[Harness Engineering][harness] principles. It shows the full closed loop:

> **read protocol → retrieve skills → ask experts → generate adapter →
> self-verify → write back skills**

…all the way to a green sandbox run, with NO LLM API key required (template
mode by default).

This demo is the "show, don't tell" companion to a series of conversations
about how to use agents for ad-tech RTA work. The conversations sit at this
order of abstraction:

1. *Why agents fit RTA* — high-frequency, repetitive, verifiable work.
2. *How to build the knowledge base* — start with "ask humans", sink to skills.
3. *Where Hermes / Claude Code fit* — they're the runtime, you supply the domain.
4. *What ties it all together* — Harness Engineering: `Agent = Model + Harness`.
5. **This demo** — a working harness instantiation you can run, modify, break.

## Requirements

- **Python 3.9+** (uses `str.removeprefix` and PEP 585 builtin generics; tested on 3.12)
- **PyYAML** (only runtime dep; `pip install -r requirements.txt`)
- *Optional:* `anthropic` SDK if you want `--llm` mode (`pip install -r requirements-llm.txt`)
- *Optional:* `pytest` to run the test suite

## 30-second quickstart

```bash
cd demos/rta-agent
pip install -r requirements.txt        # just PyYAML

python agent.py integrate bearads      # watch the loop run end-to-end

python -m pytest tests/ -v             # 4 tests, all green
```

You'll see the agent:

1. Read `protocols/bearads.md` (the media's spec)
2. Retrieve 3 already-sunk skills that apply
3. Identify 2 unresolved questions, route them to experts (`zhangsan`, `wangwu`)
4. Get canned answers (in this demo) and use them in codegen
5. Generate `adapters/bearads.py` (template mode; pass `--llm` to delegate to Claude)
6. Run the four-sensor verify suite — schema check, 100-request replay,
   p99 latency budget, reconciliation parity
7. Sink the new Q&A into `skills/rta.bearads.*.md`

Then run it a second time:

```bash
rm adapters/bearads.py
python agent.py integrate bearads     # asks 0 questions this time
```

This is the complibition curve made visible. The harness doesn't get smarter
because the model got smarter — it got smarter because the loop wrote things down.

## How this maps to Harness Engineering

| Anthropic Harness Engineering concept | Where it lives here |
|---|---|
| **Guides** (feedforward steering) | `CLAUDE.md`, `protocols/`, `experts.yaml`, `pitfalls.md`, `skills/` |
| **Sensors** (feedback verification) | `tools/verify.py`, `sandbox/server.py` |
| **Tools** | `tools/*.py` |
| **Permissions / safeguards** | `policy.yaml` |
| **Memory** | `skills/`, `asks/` (both on-disk, git-tracked) |
| **Sub-agent / delegation** | `tools/generate_adapter.py` calls Claude in `--llm` mode |
| **Self-verification loop** | `agent.py` step 5 → `tools/verify.py` → block step 6 if fail |
| **Context engineering** | `CLAUDE.md` is the entry; `_keywords_from_spec()` extracts triggers |

And the [5-step minimum closed loop][min-loop]:

| Step | Implementation |
|---|---|
| 1. Pick task | `agent.py integrate <media>` |
| 2. Map context | step 1 + step 2 of `agent.integrate()` |
| 3. Write rules (guardrails) | `policy.yaml`, `pitfalls.md`, retrieved `skills/` injected into codegen |
| 4. Self-verify | `tools/verify.py`'s 4-sensor suite |
| 5. Write back | `agent.py` step 6 → `tools/write_skill.py` |

## Running with a real LLM

Default mode generates adapters from a deterministic template — works without
any external dependency. To delegate the actual code-writing to Claude (the
"Hermes-style" pattern where the agent calls a coding-specialist sub-agent):

```bash
pip install -r requirements-llm.txt
export ANTHROPIC_API_KEY=...
python agent.py integrate bearads --llm
```

The verify gate is the same in both modes — Sensors don't care who wrote
the code.

## Where this would fit in a real Hermes deployment

Hermes Agent (Nous Research) gives you the runtime substrate: control loop,
multi-platform messaging, persistent memory, skill auto-generation. To
deploy this demo on Hermes, you'd:

1. Move `tools/*.py` → Hermes MCP server (each tool becomes one MCP tool).
2. Move `skills/` → `~/.hermes/skills/rta/` (Hermes' skill format is the
   same shape — markdown with front-matter).
3. Replace the canned `ask_expert` with Hermes' Slack/Feishu/Telegram adapter,
   so questions are real DMs to humans instead of registry lookups.
4. Wrap `agent.py`'s loop as a Hermes "task" so it's invoked by `@bot integrate <media>`.

The loop, the Guides, and the Sensors stay exactly the same. That's the
point of separating *what the agent does* from *what runs the agent*.

## Tests

```bash
python -m pytest tests/ -v
```

- `test_reference_adapters.py` — both reference adapters always pass verify.
- `test_agent_integrates_bearads.py` — agent.integrate runs end-to-end and
  produces a verified adapter + at least one new skill.
- `test_pitfall_enforcement.py` — a deliberately-buggy adapter is **caught**
  by sensors. (This is the proof that Sensors are doing their job, not just
  passing on the happy path.)

## What this demo deliberately does NOT include

(So you don't think it's a real production thing.)

- **No real media credentials.** Sandbox is in-process, secrets are demo-only.
- **No actual messaging integration.** "Ask expert" returns canned answers;
  the real version posts to Slack/Feishu and waits for a reply.
- **No vector retrieval / embedding store.** Skill search is keyword-based.
  Real Hermes uses FTS5; if you have ≫1000 skills, swap it in.
- **No real `claude-code` invocation by default.** Template mode covers ~80%
  of code shape; pass `--llm` to actually delegate to Claude.
- **No LLM in the loop unless you ask.** Demo runs deterministically so it's
  easy to reason about and easy to test.
